# 네이버 부동산 시세 자동 수집 + 임장보고서

구글 시트에 관심 있는 아파트 단지를 정리해두면, 명령 한 번으로 **네이버 부동산에서 최신 시세를 긁어와** 매매/전세 최저·최고가를 채워주고, 전체 단지를 매매가 순으로 정렬한 **순위 탭**을 만들어줍니다. 여기서 한 걸음 더 나아가 그 데이터를 예쁜 **React 임장보고서 대시보드**(필터·차트·표)로도 자동 변환합니다.

개인용 부동산 리서치를 자동화하려고 만든 도구예요. 코드를 조금이라도 다룰 줄 안다면(터미널 명령어 복붙 수준) 따라할 수 있도록 최대한 자세히 적었습니다.

## 이 도구가 하는 일

1. **시세 갱신** — 구글 시트의 동별 탭에 적어둔 네이버 부동산 링크로 매매/전세 시세를 조회해서 4개 컬럼(매매최저가/층/전세최고가/층)만 자동으로 채웁니다. 다른 컬럼(갭, 전세가율 등 수식)은 건드리지 않습니다.
2. **순위 탭** — 시트 안 모든 동의 매물을 매매최저가 내림차순으로 정렬한 통합 랭킹 탭을 자동 생성/갱신합니다.
3. **임장보고서** — 순위 탭 데이터를 가지고 법정동 필터, 검색, 요약 카드, 매전갭 차트, 평형×매매가 산점도, 전체 매물 테이블이 있는 단일 파일 React 대시보드(`App.jsx`)를 만들어줍니다.

## 0. 준비물

- **Node.js 22 이상** — [nodejs.org](https://nodejs.org)에서 LTS 버전 설치. 터미널에서 `node -v` 로 확인.
- **구글 계정** — 시트를 만들고 구글 클라우드에서 서비스 어카운트를 발급받는 데 필요합니다 (무료).
- **네이버 부동산에서 조사할 아파트 단지 링크** — 나중에 시트에 붙여넣을 거예요.

임장보고서를 브라우저로 직접 보려면 추가로:
- **React 프로젝트** (React + Tailwind CSS + Recharts) — 아래 "임장보고서 미리보기" 절에서 처음부터 만드는 법을 안내합니다.

## 2. 구글 클라우드 서비스 어카운트 만들기

이 프로그램은 여러분 대신 구글 시트를 읽고 쓸 "로봇 계정"(서비스 어카운트)이 필요합니다. 한 번만 설정하면 됩니다.

1. [Google Cloud Console](https://console.cloud.google.com/)에 접속해서 새 프로젝트를 만듭니다 (이름은 아무거나, 예: `realestate-tracker`).
2. 좌측 메뉴 **APIs & Services → Library** 로 이동 → **Google Sheets API** 검색 → **Enable(사용 설정)** 클릭.
3. **APIs & Services → Credentials** 로 이동 → 상단 **+ Create Credentials → Service account** 클릭.
4. 이름을 아무거나 입력하고(예: `sheets-bot`) 계속 진행해서 서비스 어카운트를 만듭니다. 역할(Role)은 지정하지 않아도 됩니다.
5. 만들어진 서비스 어카운트를 클릭 → **Keys** 탭 → **Add Key → Create new key → JSON** 선택 → 다운로드.
6. 다운로드된 JSON 파일을 이 저장소 폴더 안에 `.secrets/service-account.json` 으로 저장하세요 (폴더가 없으면 새로 만들면 됩니다). 이 파일은 절대 다른 사람과 공유하거나 GitHub에 올리면 안 됩니다 (`.gitignore`에 이미 제외되어 있음).
7. 다운로드한 JSON 파일을 열어서 `client_email` 값을 복사해두세요. 예: `sheets-bot@realestate-tracker-123456.iam.gserviceaccount.com` — 다음 단계에서 이 이메일을 시트에 "편집자"로 초대해야 합니다.

## 3. 구글 시트 준비하기

### 3-1. 새 스프레드시트 만들기

[sheets.google.com](https://sheets.google.com)에서 새 스프레드시트를 만드세요. 시트 제목은 여러분이 조사할 지역명으로 하는 게 좋습니다 (예: "경기도 의왕시") — 이 제목이 나중에 임장보고서의 제목으로 자동으로 쓰입니다.

### 3-2. 동별 탭 만들기

조사하려는 **법정동마다 탭을 하나씩** 만드세요. **탭 이름은 반드시 '동'으로 끝나야 합니다** (예: `가락동`, `인덕원동`) — 이 규칙으로 프로그램이 어떤 탭이 매물 데이터인지 자동으로 찾습니다.

각 탭은 아래 22개 컬럼을 정확히 이 순서로, 3번째 줄(A3부터)에 헤더로 넣어야 합니다 (1~2행은 비워두거나 메모용으로 써도 됩니다):

```
단지명 | 입주연도 | 총세대수 | 공급(m2) | 공급면적 | 전용(m2) | 전용면적 | 세대 |
매매최저가 | 층 | 전세최고가 | 층 | 매전갭 | 전세가율 | 매매평단 | 전세평단 |
방 | 욕실 | 구조 | 매/전/월Type | 비고 | 링크
```

- **매매최저가/전세최고가/링크** 3개 헤더만 정확히 있으면 나머지는 프로그램이 알아서 위치를 찾습니다 (헤더 텍스트의 띄어쓰기·줄바꿈은 무시됩니다).
- **링크** 컬럼에는 네이버 부동산 단지 페이지 URL을 넣으세요. 네이버 부동산(new.land.naver.com)에서 관심 단지를 검색 → 평형 필터를 적용한 뒤 주소창의 URL을 그대로 복사하면 됩니다 (`?...&h=최소면적&i=최대면적` 형식이 포함되어야 정확한 평형만 조회됩니다).
- 매매최저가/전세최고가/층 값은 비워두세요 — 프로그램이 채워줍니다.

예시 한 줄이 필요하면 [`docs/example-dong-sheet.csv`](docs/example-dong-sheet.csv) 파일을 구글 시트에 **파일 → 가져오기 → 업로드 → "새 시트로 삽입"** 으로 불러온 뒤 탭 이름을 `OO동`으로 바꾸고 내용을 채워 넣으세요.

### 3-3. 서비스 어카운트를 편집자로 공유

시트 오른쪽 위 **공유** 버튼 → 2단계에서 복사해둔 서비스 어카운트 이메일 입력 → 권한을 **편집자**로 지정 → 공유. (알림 이메일은 안 보내도 됩니다.)

> ⚠️ 뷰어(보기 전용) 권한만 주면 `403: The caller does not have permission` 에러가 납니다. 반드시 편집자 권한이어야 합니다.

### 3-4. 시트 ID 확인

시트 주소창의 URL에서 `/d/`와 `/edit` 사이 문자열이 시트 ID입니다:

```
https://docs.google.com/spreadsheets/d/이_부분이_시트_ID/edit
```

## 4. 설치 및 환경 설정

```bash
npm run setup
```

Node 버전 확인, 서비스 어카운트 키 자동 탐색, `.env` 파일 생성, 테스트 실행, 시트 연결 점검까지 한 번에 해줍니다. 실행 후 `.env` 파일을 열어서 비어있는 값이 있으면 채워주세요:

```bash
# .env
RE_SHEET_ID=위에서_확인한_시트_ID
RE_SHEETS_KEY_JSON=.secrets/service-account.json
RE_DRY_RUN=1
```

`setup` 스크립트를 다시 실행하면 채워진 값이 맞는지 재확인합니다.

## 5. 실행하기

### 5-1. 리허설(dry-run) — 시트에 아무것도 쓰지 않고 결과만 확인

```bash
npm run update:dry -- --dong <동이름>
```

`실패 0 / ok N`이 나오면 정상입니다. 문제가 있으면 [트러블슈팅](#7-자주-나오는-문제)을 확인하세요.

### 5-2. 실제 시세 갱신 (해당 동만)

```bash
RE_DRY_RUN=0 npm run update -- --dong <동이름>
```

시트를 열어서 매매최저가/전세최고가/층 4컬럼만 채워졌는지 확인하세요.

### 5-3. 전체 동 한 번에 갱신 (+ 순위 탭 자동 생성)

동 이름을 하나하나 나열할 필요 없이, 시트에 있는 '동'으로 끝나는 탭을 자동으로 찾아서 전부 처리합니다:

```bash
RE_DRY_RUN=0 npm run update
```

**시세 갱신이 끝나면 순위 탭도 자동으로 함께 갱신됩니다.** 시트에 `순위`라는 탭이 새로 생기거나 갱신되어 있을 거예요.

동 개수와 단지 수에 따라 몇 분에서 수십 분까지 걸릴 수 있습니다 (네이버 서버에 부담을 주지 않도록 요청 사이 약 2초씩 간격을 둡니다). 진행 상황은 `outputs/real_estate/run.log.jsonl` 에서 실시간으로 확인할 수 있습니다.

### 5-4. 순위 탭만 다시 정렬 (시세는 그대로)

```bash
npm run ranking
```

## 6. 임장보고서(React 대시보드) 만들기

순위 탭이 채워진 다음, 아래 명령 한 줄이면 대시보드 파일이 만들어집니다:

```bash
npm run report -- --out App.jsx
```

`App.jsx` 파일 하나에 데이터와 화면이 전부 들어있습니다 (React + Tailwind CSS + Recharts). 법정동 필터, 단지명 검색, 요약 카드, 매전갭 차트, 평형×매매가 산점도, 전체 매물 테이블이 포함됩니다.

### 이 파일을 브라우저로 보려면

React 프로젝트가 없다면 아래처럼 새로 하나 만드세요 (한 번만 하면 됩니다):

```bash
npm create vite@latest my-report -- --template react
cd my-report
npm install
npm install recharts tailwindcss @tailwindcss/vite
```

`vite.config.js` 를 아래처럼 수정:

```js
import react from '@vitejs/plugin-react'
import tailwindcss from '@tailwindcss/vite'
import { defineConfig } from 'vite'

export default defineConfig({
  plugins: [react(), tailwindcss()],
})
```

`src/index.css` 내용을 전부 지우고 한 줄만 남기기:

```css
@import "tailwindcss";
```

그다음 아까 만든 `App.jsx` 를 `my-report/src/App.jsx` 자리에 덮어쓰고:

```bash
npm run dev
```

터미널에 뜨는 주소(보통 `http://localhost:5173`)를 브라우저에서 열면 임장보고서가 보입니다.

## 7. 자주 나오는 문제

| 증상 | 원인 / 조치 |
|------|-----------|
| `Sheets API 403: does not have permission` | 서비스 어카운트를 시트에 **편집자**로 공유하지 않음 — 3-3 다시 확인 |
| `Sheets API 400: document must not be an Office file` | 엑셀(.xlsx) 파일을 드라이브에 올린 것 — 시트를 열고 **파일 → Google 스프레드시트로 저장**으로 변환 |
| `헤더 행을 찾지 못했습니다` | 탭의 헤더에 "매매최저가/전세최고가/링크" 텍스트가 정확히 없음 — 3-2 형식 재확인 |
| `연속 5회 실패 — 전체 중단` | 네이버가 일시적으로 요청을 막았거나 네트워크 문제 — 30분 정도 기다렸다가 재실행 |
| `RE_SHEET_ID 환경변수가 필요합니다` | `.env` 파일에 `RE_SHEET_ID` 값이 비어있음 |
| `서비스 어카운트 JSON 파일이 없습니다` | `.env` 의 `RE_SHEETS_KEY_JSON` 경로가 실제 파일 위치와 다름 |

## 8. 안전 장치 (알아두면 좋은 것들)

- **기본값은 항상 dry-run** — `RE_DRY_RUN=0` 을 직접 지정해야만 시트에 실제로 씁니다. 실수로 시트를 망가뜨릴 걱정 없이 마음껏 연습해보세요.
- **시세 갱신은 4개 컬럼만 건드립니다** — 매매최저가/층/전세최고가/층 외에 갭·전세가율 등 여러분이 만든 수식은 절대 건드리지 않습니다.
- **모든 실행 기록이 남습니다** — `outputs/real_estate/snapshots/`에 날짜별 스냅샷 JSON, `outputs/real_estate/run.log.jsonl`에 실행 로그가 쌓입니다.
- **문제가 생기면 구글 시트 자체의 버전 기록**(파일 → 버전 기록 → 버전 기록 보기)으로 언제든 되돌릴 수 있습니다.
- 개인 리서치 용도로 만든 도구입니다. 짧은 시간에 너무 많은 요청을 보내면 네이버가 일시적으로 차단할 수 있으니, 대량의 동/단지를 한 번에 돌리기보다는 필요한 만큼만 나눠서 실행하는 걸 권장합니다.
